# Fresh architecture

- `ai-studio-frontend/src/`: supplied React + TypeScript UI, own CSS tokens and components. This supersedes the old packages/design-system. No renderer Node/Electron access.
- `desktop/main.ts`: Electron lifecycle, native folder chooser, named IPC. Renderer is sandboxed and isolated; unexpected navigation/popups/webviews and permissions are blocked. Sender identity and exact main-frame URL are checked.
- `desktop/preload.ts`: named typed methods, no raw IPC or arbitrary file/network access.
- `shared/desktop.ts`: bridge contract and strict runtime settings schema, using existing frontend types.
- `desktop/settings-store.ts`: versioned JSON for small preferences only. Serialized writes, flushed temporary file and atomic rename. Corrupt/unsupported data blocks writes without destroying the original. SQLite library storage lives in desktop/library/store.ts; see PHASE3.md.
- `tests/`: real persistence, malformed-input and sender validation tests.

Settings live under Electron's appData / Castbox Fresh / settings.json, isolated from previous implementations. Destination paths are preferences, not arbitrary renderer file-write authorization. New paths must come from the native chooser. Phase 4 implements session-only opaque grants, realpath/symlink checks and filename safety for read-only planning. Transfers create exclusive private partial files, verify saved bytes, validate destinations around writes, and publish complete files atomically. Preflight/path snapshots cannot prevent every hostile local filesystem race; only tested on macOS. See PHASE4.md.

Native preferences load before rendering. Load/save failure is visible; native mode never falls back to browser storage. Browser-only preview retains existing prototype behavior. Theme still uses the original localStorage implementation. Settings reset retains the selected destination. Native Settings, Downloads and review use the OS folder chooser. Native review prepares and persists file plans through desktop/downloads; browser-only bulk controls remain the prototype. SQLite v3 stores plans and reservations separately from persistent transfer runs/jobs. SQLite v5 adds ordered playback queue and saved local playback positions/durations.

Build the original Vite 8 UI with a relative asset base and bundle desktop/preload separately with esbuild. Existing fonts still load from Google Fonts, as in the supplied export; bundle matching fonts before offline release. Production CSP limits script to self and restricts resource origins. It retains a loopback HMR connection allowance for browser development, which should be split out during release hardening.

The Phase 1 catalog client in `desktop/catalog/client.ts` implements anonymous search, suggestions, channel details, episode index, batch and single-episode metadata with named IPC. Fresh daily parameters follow the public web client; no captured credentials are used. Production catalog registration is shared with a real Electron test harness. NativeApp.tsx selects the real catalog UI; App.tsx keeps the browser-only fixture prototype. LiveCatalog owns navigation, pagination, session selection, retry and stale-response guards. catalog/model.ts maps nullable API metadata into existing view types, renders descriptions as plain text and parses full Castbox links. Native catalog:artwork accepts only HTTPS URLs on the fixed observed CDN allowlist, refuses redirects and SVG, caps bodies at 1 MiB with an 8-second deadline, and returns data URLs. CSP allows only the named local `castbox-media:` scheme for audio. The renderer bounds its artwork cache to 40 entries and serializes fetches. Unsupported images show neutral placeholders. Native saved channels persist in SQLite through library:read and library:set-saved. TransferEngine resolves fresh media sources through main-process IPC, restricts redirects and public DNS addresses, streams MP3/M4A/AAC/Ogg/Opus/WAV/FLAC into bounded partial files, checkpoints SHA-256 prefixes, and stores durable transfer records. PlaybackController issues expiring opaque capabilities only for completed local files and streams checked byte ranges; the renderer owns one audio element and uses typed playback IPC for queue and progress. Storage IPC reports completed transfer bytes, destination-volume capacity and Electron session cache size; clearing only calls Electron's cache API and never removes downloaded media. See API_EVIDENCE.md and PHASE6.md; credentials from files.txt are never used. Targeting macOS/Windows/Linux requires separate packages and actual testing on each OS.
